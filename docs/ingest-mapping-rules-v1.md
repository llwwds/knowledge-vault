## 四、路径映射规则

**规则**
1. **默认映射函数（1:1 保真）**：`目标相对路径 = 快照相对路径`。目录层级、目录名、文件名全部原样（含空格与中文；URL 编码不做解码）。
2. **特例重定向表**（仅少数根部文件，逐条列出、审批后生效）：
   - 根部 2 个凭据类笔记 → 重定向至 `04 信息/042 个人的 key 等信息/`（见 Q3）。
   - 根部 2 个业务文件（md+canvas 成对）→ 候选：`00 收集箱/000 暂未处理/`（见 Q2）。
   - 库级定义文件 → 目标区根部（唯一允许落到根部的普通文件）。
3. **重名冲突处理（Q5）**：默认映射下同一路径不可能冲突（源目录内同名唯一）；冲突仅可能来自特例重定向与大小写折叠。两个选项：
   - 选项 A（**推荐**）：拒绝 + 报告。manifest 中标记 `CONFLICT`，该文件不入本批，人工裁决后重跑。理由：目标系统「移动/重命名 = 判删除 + 新建」，首次入库就应保持 id-路径关系干净。
   - 选项 B：自动追加序号后缀 ` (2)`。省一次人工，但产生历史上不存在的文件名，引用保真被破坏。
4. macOS 大小写不敏感文件系统导致的潜在折叠冲突：源快照本身已在该文件系统上拷贝生成，实测不存在此类对；manifest 生成阶段仍做一次大小写折叠检查兜底。

**依据**：1:1 映射使「快照相对路径 → file_id」成为纯函数，manifest、断点续传、校验全部可简化；特例重定向控制在个位数。

## 五、登记规则

**规则**（字段定义以设计定稿为准：documents 表 15 字段，SQLite index.db，WAL）

1. **file_id 分配顺序（遍历序）**：迁移清单生成时，对「排除后全量文件清单」按**快照相对路径的 UTF-8 字节字典序**排序，file_id 从 1 起单调递增、一次定死、永不回收。排序纯函数化，任何重跑/断点恢复都得到同一 id。后续增量入库由 API 按同规则递增分配。
2. **content_hash**：所有登记文件（含 >50MB 与 0 字节）计算 sha256 取前 12 位。0 字节文件即空串 hash。不计算排除项。
3. **created_at 取值（建议，Q 默认规则）**：md 有 frontmatter 日期字段（`created`/`created_at`/`date`/`datetime`，能解析为日期）→ 归一化为 ISO-8601 使用；否则用文件 mtime。非 md 文件一律用 mtime。依据：抽样中 17% 有 fm 日期字段且格式以 ISO 为主；mtime 97% 在 2026 年，可信。
4. **modified_at**：fm `modified_at`/`updated` 优先，否则文件 mtime。documents 表的 `mtime` 字段独立记录文件系统 mtime（文件事实），与 frontmatter 真源字段并存，互不覆盖。
5. **title**：fm `title` 非空 → 用之；否则文件名去扩展名（md 与非 md 同规则）。
6. **context_tag 初值**：取该文件相对路径**前 3 层目录名**的 JSON 数组，如 `["02 项目", "021 专业项目", "0212 公司项目"]`；根部文件为 `[]`。依据：与分类树判据对齐，tag 数可控（唯一索引序）且过滤粒度足够。更深目录不进 tag（避免爆炸，Q7 提供备选）。
7. **status 初值**：默认 `library`。`now` 的自动判定不做（Q6），理由：首入库对内容语义无了解，误标影响召回排序；用户可在库内随时改 frontmatter（真源）并触发索引更新。
8. **registered_at / updated_at**：登记时刻。
9. **软删除预置**（仅当 Q1 选 B）：废纸篓文件 `deleted_at` = 登记时刻，其余同规则。

## 六、frontmatter 处理

**规则**
1. **已有 frontmatter 的 md**：原字段、原值、原顺序全部保留（含 `tags`、`created`、回执类 `record_id`/`phase` 等自有 schema）；仅**追加**缺失的标准字段，缺什么补什么。已有 `created` 不改名不删除，另补 `created_at`（值优先取自 `created`）。
2. **无 frontmatter 的 md**：在文件头插入最小 7 字段块：
   ```yaml
   ---
   file_id: <分配的 id>
   title: <按第五节规则>
   context_tag: [<路径前 3 层目录名>]
   created_at: <按第五节规则>
   modified_at: <按第五节规则>
   summary:
   status: library
   ---
   ```
3. **summary 一律留空**（空值），禁止任何自动生成或人工代写；后续由用户逐步填写，填写后由管线补 kind=summary 记录（见第七节）。
4. **非 md 文件一律不改写本体**（二进制不可写；文本类非 md 也不插 frontmatter）。非 md 的 7 字段元数据仅存在于 index.db（documents 行），frontmatter 真源约定仅对 md 生效；非 md 的 summary 留待人工填写（填入登记表并在 frontmatter 缺席是允许的例外，见 Q11）。
5. **改写原则**：只增不改；不触碰正文；不改行尾与编码（UTF-8）；改写通过「临时文件 + 原子替换」完成，替换前保留原文件副本于设备本地备份目录。
6. 0 字节 md（15 个）：按「无 frontmatter」生成 7 字段块，正文为空。

**依据**：抽样显示既有字段以 `title/tags/created` 与回执 schema 为主，与 7 字段规范无冲突；「只加不改」保证对用户的 Obsidian 视图零破坏。

## 七、入库索引规则

**规则**
1. **切块对象（Q8）**：推荐 v1 仅对 **md 与 txt** 切块；csv/json/jsonl/py 等结构化与代码文件 v1 **只登记不切块**（后续版本再评估扩展）。依据：内容区 9,185 个 md 是知识主体（仅 70.8MB）；csv/json 大头是实验数据导出（56GB+），切块产生巨量低质 chunk；教程仓库 .py 为只读参考，检索价值低于噪音成本。
2. **≤50MB 切块参数（默认值，靠后网格实验定）**：md 按标题层级切块，默认切点为二级标题（`##`）；无标题 md 按固定长度切；单 chunk 默认目标 ~800–1,000 字符、重叠默认 ~100 字符（**标注：参数靠后网格实验定，v1 先用默认值跑通**）。txt 按固定长度+重叠切。
3. **chunk 存储**：chunk 原文只写 index.db 的 chunks 表；zvec payload 只存 id + 元数据（不存原文）。jieba 预分词启用 userdict_v0（24 条）；摄入侧对 `_` / `/` 做 span 预处理（保护或归一化），查询侧镜像同一处理。
4. **>50MB 文件**：本体不入向量库；仅登记（documents 行，is_large=1）。其 summary 独立记录入向量库的前提是 summary 非空——v1 初始 summary 全空，故大文件 v1 只有登记行、无向量记录；用户填写 summary 后管线补入。
5. **kind=summary 推广**：任何文件（md 或非 md、任意大小）summary 非空即生成一条 summary 记录入向量库。v1 初始为空集，规则生效于后续填写动作。
6. **图片/附件**：不切块不入向量库，仅登记（一文件一登记行）。**一图一引用**：被多个 md 引用的图片**不复制、不去重**——file_id 与物理文件 1:1 严格绑定，多引用关系属于 edges 图层的职责（md→附件边，后续版本建）；v1 靠目录结构保真维持引用路径有效。
7. **重复内容**：不做内容级去重（13.76% 重复率集中在实验产物与教程仓库；全部入向量仅增加 ~0.35GB 等量文本）。检索按 file_id 归并；登记层 content_hash 已支持后续重复分析。
8. **deleted_at 非空的登记行**（废纸篓，若 Q1 选 B）：不切块、不入向量库。

## 八、敏感文件处理

**规则**
1. **判定机制 = 清单驱动 + 模式兜底**：以设备本地的疑似敏感清单（快照分析产出，126 项）为基线，加上 `04 信息/041`、`04 信息/042` 全目录、044 下凭据类文件；入库管线运行时再按文件名模式（api key/token/secret/password/凭据/账号/密码/密钥等 + 凭据类扩展名）兜底扫描一次。清单本身只存设备本地，不入仓库。
2. **处置两选项（Q9 前置）**：
   - 选项 A：完全跳过——不拷贝、不登记。缺点：file_id 全覆盖被破坏，且「不登记」与「登记但不索引」在隐私上无差别（登记表只含元数据，同样在本地）。
   - 选项 B（**推荐**）：**正常拷贝 + 正常登记 + 排除向量库**。凭据内容无检索价值，却会长期占据向量索引并放大泄露面；登记行保留可检索「有哪些凭据文件」的目录能力（按 title/路径）。
3. **04 信息隐私分级（Q10）**：
   - 041 / 042：最高敏。推荐：登记 + **排除向量库**，内容永不解析（v1 分析即未读取其内容，后续管线同样跳过）。
   - 044：公司凭据类文件排除向量库；其余登记。
   - 043：大学文件（11.69GB，照片/视频/PDF）。推荐 v1 **整体排除向量库**（多媒体本就不切；PDF 文本切块会把含姓名的个人信息写入索引）。候选：文档类 ≤50MB 的 PDF 允许切块入向量（检索价值 vs 隐私，见 Q10）。
4. **02 项目/0212 公司项目（Q12）**：1,779 个 md（工作记录、实验记录）检索价值高；系统为单机本地、无外发面。推荐：**照常切块入向量库**（本地索引不违反「公司数据不出本地」的既有红线；红线针对的是仓库、日志、云端与库外副本）。备选：0212 全目录排除向量库，只登记。
5. 真实文件名/内容/清单不写入任何仓库文件、日志与对话输出；manifest 与敏感清单只落设备本地目录。

## 九、执行、校验与断点

**规则**
1. **先 manifest，后执行**：执行前一次性生成迁移清单 manifest（JSONL，设备本地），字段：`source_rel / target_rel / size / sha256 / file_id / batch / state / error`；state 状态机 `pending → copied → verified → registered → failed`（另含 `excluded`、`conflict`）。file_id 在 manifest 生成时预分配，执行期不再变动。
2. **分批（先小后大、先 md 密集后数据密集，尽早暴露管线问题）**：

| 批次 | 范围 | 文件数 | 体量 |
| --- | --- | --- | --- |
| B0 引导验证 | 根部文件 + assets + 00 收集箱 | ~590 | 0.06 GB |
| B1 | 03 笔记 + 顶层 03 Subagent | ~2,640 | 0.33 GB |
| B2 | 01 资料 | 14,418 | 1.08 GB |
| B3 | 02 项目（0211/0213/022） | ~923 | 0.59 GB |
| B4 | 04 信息 | 1,399 | 11.66 GB |
| B5 | 02 项目/0212 公司项目 | 31,600 | 74.61 GB |
| B6 | 99 废纸篓（仅当 Q1 选 B） | 1,478 | 0.05 GB |

3. **每批三步，顺序固定**：① 拷贝（保留 mtime）→ ② 逐文件 sha256 校验（与 manifest 比对；失败重试 1 次，再失败标 `failed` 人工处理）→ ③ 登记（先拷贝校验后登记，禁止颠倒）。
4. **登记方式**：首次入库为一次性引导，由引导脚本直接写 index.db（WAL 模式）；此为唯一绕过 API 的写入例外，完成后运行期写入一律走 API 入口（与「写入控制仅在 API 入口」定稿的边界说明）。
5. **断点续传**：以 manifest 为唯一进度真源；重跑自动跳过 `registered`；`failed/conflict` 行人工裁决后单独重放。
6. **回滚原则**：批级回滚——该批已登记行置 `deleted_at`（软删），已拷贝文件移入设备本地隔离目录，不动正式区其他批次；frontmatter 改写保留原文件副本，可整批还原。
7. **幂等性**：拷贝前若目标存在且 hash 一致则跳过；登记按 file_id `INSERT OR IGNORE`。
8. **全程只读约束**：源快照零写入、零 touch、零 chmod、零移动；迁移为「复制」而非「移动」。
